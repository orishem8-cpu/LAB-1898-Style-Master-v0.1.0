# LAB 1898 — Style Master: быстрый старт

## Что находится в архиве

Это исходный инженерный прототип VST3-плагина и Standalone-приложения на C++17 + JUCE 8. Интерфейс повторяет структуру присланного референса: три панели, мягкий светлый neumorphic-дизайн и оранжевый акцент.

Реализованы восемь стилевых окраcок, макроконтролы, EQ, сатурация с компенсацией DC от Bias, гармонический слой, компрессия, mid/side width, Dry/Wet, плавный Bypass/Power, спектроанализатор, RMS/Peak-индикация, загрузка аудиореференса в фоновом потоке, базовый Auto Match, A/B-снимки и сохранение состояния проекта.

## Сборка на Windows 10/11 x64

Нужны:

- Visual Studio 2022 или новее, workload **Desktop development with C++**;
- CMake 3.22+;
- Git в `PATH`;
- подключение к интернету при первой конфигурации (CMake скачивает JUCE 8.0.17-security).

Открой PowerShell в корневой папке проекта и выполни:

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release --target LAB1898StyleMaster_VST3
```

VST3 обычно появится здесь:

```text
build/LAB1898StyleMaster_artefacts/Release/VST3/LAB 1898 Style Master.vst3
```

Скопируй `.vst3` в системную VST3-папку Windows и выполни повторное сканирование плагинов в FL Studio. Для диагностики можно сначала собрать Standalone:

```powershell
cmake --build build --config Release --target LAB1898StyleMaster_Standalone
```

## Сборка через GitHub Actions

1. Создай пустой репозиторий GitHub.
2. Распакуй архив и загрузи **содержимое** папки `lab1898_project` в корень репозитория.
3. Выполни commit и push в ветку `main` (или `master`).
4. Открой вкладку **Actions** и дождись завершения workflow `Windows VST3 build`.
5. Скачай артефакт `LAB-1898-Style-Master-VST3` из завершённого запуска workflow.

Workflow завершится ошибкой, если VST3-бандл не был создан.

## Важные ограничения прототипа

- Это **v0.1 engineering prototype**, а не готовый коммерческий мастеринг-процессор.
- Встроенный выходной safety stage ограничивает sample peaks мягкой характеристикой, но не является oversampled true-peak limiter.
- Измеритель показывает RMS и sample peak в dBFS, а не LUFS и true peak.
- Reference Match анализирует первые 45 секунд файла и сравнивает широкие low/mid/high energy shares вместе с RMS/peak. Это стартовая тональная подсказка, не полноценное перцептуальное или фазовое совпадение мастеринга.
- Нелинейная обработка пока не oversampled. Перед коммерческим релизом нужны тесты алиасинга, oversampling, измерения, loudness-matched прослушивание и проверка в FL Studio на реальных проектах.
- Сборка в среде создания архива не была выполнена: среда не смогла разрешить `github.com`. Архив содержит исходники и CI workflow, но его нужно впервые собрать в GitHub Actions или локально.

Подробности DSP и чек-листы находятся в `docs/` и `README.md`.
